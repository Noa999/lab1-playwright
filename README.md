## Юу хийсэн бэ

[saucedemo.com](https://www.saucedemo.com) демо дэлгүүрийн нэвтрэх болон сагслах урсгалыг Playwright (TypeScript, Chromium) ашиглан автоматжуулсан. Бүх тест `tests/mytest.spec.ts` файлд байна.

| # | Тест | Юуг шалгадаг |
|---|------|--------------|
| 1 | амжилттай нэвтрэх | `standard_user` нэвтэрч, `inventory.html` руу шилжиж, `Products` гарчиг харагдаж, logout хийсний дараа нэвтрэх хуудас руу буцдаг |
| 2 | буруу нууц үгээр нэвтрэхэд алдаа гарна | Алдааны мессеж гарч, хэрэглэгч нэвтрэх хуудсандаа үлддэг |
| 3 | түгжигдсэн хэрэглэгч нэвтэрч чадахгүй | `locked_out_user` дээр "locked out" мессеж гарна |
| 4 | барааг сагсанд нэмэх | Бараа сагсалж, тоолуур 1 болж, сагсанд тэр бараа харагдаж, logout хийж дуусна |

Нэвтэрсэн тест бүр `logout()` туслах функцээр төгсөж, URL-ээ шалгадаг. Тест бүр өөрийн browser context-д ажиллах тул хоорондоо хамааралгүй (test isolation).

## Хэрхэн ажиллуулах

```bash
npm install
npx playwright install chromium
npx playwright test
```

Хадгалсан нотолгоог харах:

```bash
npx playwright show-report docs/playwright-report
npx playwright show-trace docs/trace-failed-assertion.zip
```

## Нотолгоо (`docs/` хавтас)

- `docs/playwright-report/` нь 4 тест бүгд ногоон гарсан HTML report ба тест бүрийн trace, бичлэгтэй.
- `docs/trace-failed-assertion.zip` нь санаатайгаар унагасан тестийн trace. Сагсны тоолуурын assertion-ийг `'1'`-ээс `'2'` болгоход тест уналаа. Дараа нь буцааж засаад commit хийсэн тул repo-ийн эцсийн төлөв ногоон.
- `docs/codegen-saucedemo.ts` нь `npx playwright codegen`-ээр бичүүлсэн код (тест биш, зөвхөн харьцуулах зорилготой, `tests/` дотор биш тул ажиллахгүй).

## Ажиглалт

**XPath-аас яагаад зайлсхийсэн бэ.** XPath нь DOM-ийн бүтэц, элементийн байрлалд тулгуурладаг тул дизайнд жижиг өөрчлөлт орход тест эвдэрдэг. Харин `getByRole`, `getByPlaceholder`, `getByText` нь хэрэглэгчийн хардаг зүйл (товчны нэр, талбарын тайлбар, текст) дээр тулгуурладаг тул тогтвортой, мөн тестийн код нь уншихад ойлгомжтой. Codegen-ийн кодонд `div` + `filter` + `.nth(4)` гэсэн байрлалаас хамаарсан мөр гарсан нь яг ийм эмзэг locator-ын жишээ болсон.

**Codegen ба миний бичсэн кодын ялгаа.** Codegen нь ихэнх элементийг CSS-ээр (`locator('[data-test="username"]')`) олсон. Мөн би санамсаргүй terminal команд paste хийснийг, түүнийг буцаасныг ч бичсэн, өөрөөр хэлбэл алдаатай үйлдлийг ч алгасдаггүй. Хамгийн гол нь codegen-д нэг ч `expect` assertion байхгүй, зөвхөн үйлдлийг давтдаг тул хуудас зөв төлөвт орсныг шалгадаггүй. Миний тестүүд URL, харагдаж буй текстийг шалгадаг, туслах функцтэй, комментотой.

**Locator-ын алдаа.** Эхэндээ logout-ыг `getByRole('link', { name: 'Logout' })`-ээр олохыг оролдоход 30 секунд хүлээгээд унасан. Бичлэгт цэс нээгдээд "Logout" харагдаж байсан ч энэ элемент `link` role-тэй биш байсан. `getByText('Logout', { exact: true })` болгож засахад тест ногоон болсон.

**Trace viewer.** Санаатайгаар унагасан тестийн trace дээр алдааны шалтгаан шууд харагдсан: `Expected "2"`, `Received "1"`, мөн `getByTestId('shopping-cart-badge')` нь 14 удаа олдож `1` гэсэн утгатай байсан гэсэн call log. Элемент олдохгүй байгаа биш, хүлээсэн утга буруу байгааг тэр дор нь ойлгосон. Энгийн алдааны мессеж зөвхөн "failed" гэж хэлдэг, харин trace нь алхам бүрийн DOM-ийн агшин зуурын байдлыг үлдээдэг.

## Playwright ба Selenium харьцуулалт

Selenium-д элемент бэлэн болтол explicit wait гараар бичих шаардлагатай байдаг бол Playwright-д auto-wait байдаг. Би ямар ч `sleep` эсвэл wait бичээгүй ч тестүүд тогтвортой ажилласан. Playwright нэг командаар (`npx playwright install`) хөтөч суулгадаг, Selenium-д хөтөч бүрт тусдаа driver хэрэгтэй. Дебаг хийхэд Selenium лог, скриншотоор хязгаарлагддаг, Playwright-ийн trace viewer нь алхам бүрийн бичлэг, DOM snapshot, сүлжээний хүсэлтийг үзүүлдэг нь алдаа хайхад илүү хурдан байлаа. Codegen нь Selenium IDE-тэй төстэй боловч гаргасан код нь шууд ажиллахуйц, гэхдээ дээр дурдсанаар assertion-гүй, эмзэг locator агуулж болдог тул заавал гараар засах шаардлагатай. Лицензийн хувьд хоёулаа Apache 2.0 тул сонголтыг техникийн давуу талаар хийнэ. Миний хувьд Playwright илүү цөөн тохиргоотой, илүү хурдан эхэлдэг боловч Selenium нь олон хэл, олон жилийн туршлагатай экосистемтэй хэвээр.
